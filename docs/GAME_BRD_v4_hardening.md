## 2. Санал болгож буй сайжруулалтууд (сэдвээр бүлэглэсэн)

### A. Тест & чанарын баталгаа
- **Vitest + React Testing Library** нэмж, `Battle.jsx`-ийн HP/damage тооцоолол, `TowerView.jsx`-ийн floor-state логик (`cleared/current/locked`) зэрэг цэвэр логикт unit test бичих.
- **Playwright** (эсвэл одоо ашиглаж байгаа `claude-in-chrome` шиг browser automation-ийг script болгож хадгалах) — win/lose flow, admin regenerate flow-г автоматжуулсан smoke test болгох.
- `npm run lint` болон `npm run build`-ийг **GitHub Actions**-д холбож, PR болгонд автоматаар ажиллуулах.

### B. Найдвартай байдал / алдааны боловсруулалт
- `TowerSelect.jsx`, `TowerView.jsx`, `Battle.jsx`-ийн `catch` блокуудад **хэрэглэгчид харагдах алдааны мессеж** нэмэх (жиш: "Сүлжээний алдаа гарлаа, дахин ачаалж үзнэ үү" + "Дахин оролдох" товч).
- `App.jsx`-ийг **React Error Boundary**-гаар ороож, гэнэтийн crash үед цагаан дэлгэцийн оронд "Ямар нэг зүйл буруу боллоо" гэсэн fallback UI + "Нүүр хуудас руу буцах" харуулах.

### C. Аюулгүй байдал & өгөгдлийн загвар
- `regenerate_tower_floors()`-ийг дуудахаас өмнө admin аль категориудад materialize хэрэгтэйг харах **admin overview дэлгэц** (SQL: бүх категори + тэдгээрийн `tower_floors` тоо + `quiz_items` тоог нэг `view`-ээр нэгтгэж харуулах, зөвхөн admin-д харагдана).
- `Battle.jsx`-ийн асуулт татах query-г баримтжуулж, ирээдүйд server-side scoring руу шилжих шаардлагатай эсэхийг тэмдэглэх (v1-д хэвээр үлдээж болно, гэхдээ мэдэгдэж байх ёстой хязгаарлал).

### D. Контент удирдлагын сайжруулалт
- `QuestionManager.jsx`-д **хайлтын талбар** (асуултын текстээр) + **difficulty-ээр шүүх** dropdown нэмэх.
- Асуулт олон болоход **pagination эсвэл virtualized list** ашиглах.

### E. Хүртээмж (accessibility) нэмэлт
- `Battle.jsx`-ийн зөв/буруу сонголтод өнгөнөөс гадна **icon** нэмэх (✅/❌), зөвхөн `color`-оор ялгахгүй байх.
- Screen reader-т зориулж `aria-live` бүс нэмж, HP өөрчлөгдөх бүрд дуут мэдэгдэл өгөх (`"Дайсны HP 20 боллоо"` гэх мэт).

### F. Хөгжлийн процесс
- Одоогийн ажлыг **утга учиртай commit мессежүүдээр** (Phase тус бүрээр) git-д бичих, цаашид "fix" гэсэн ерөнхий нэр ашиглахгүй байх.
- `README.md`-д Phase 1-5-ийн тойм + SQL migration-уудыг ямар дарааллаар ажиллуулах тухай баримтжуулах.

### G. UX polish
- **Тоглогчийн ерөнхий тойм** (dashboard) — Tower Select дэлгэцийн дээд хэсэгт "Нийт X/Y цамхаг бүрэн дийлсэн" гэсэн ерөнхий индикатор.
- Дуу чимээний тохиргоог **localStorage-based volume slider** болгон өргөтгөх (одоогийн mute/unmute-ээс гадна).
- Ялалт/ялагдлын дэлгэцэд бага зэргийн CSS animation (одоогийн статик текст оронд) нэмэх.

## 4. Тэргүүлэх зэрэглэл дэх зөвлөмж

Хэрэв нэг л зүйлээс эхлэх бол: **Error Boundary + алдааны мессеж (Phase 6)** — учир нь энэ бол хэрэглэгчийн бодит туршлагад шууд нөлөөлдөг, мөн хэрэгжүүлэхэд хамгийн хямд (1-2 файл өөрчлөх төдий) зүйл.

Тестийн суурь (Phase 7) нь хожим орсон feature бүрийг илүү аюулгүй нэмэхэд тусална, гэхдээ шууд хэрэглэгчид харагдахгүй тул яаралтай биш.
